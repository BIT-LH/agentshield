## 1. 安装与运行

### 前置条件

- Python 3.8 或更高版本
- 无需任何第三方依赖

### 三种运行方式

```bash
# A. 从源码树直接运行（推荐用于试用）
python -m agentshield --help

# B. 可编辑安装（推荐用于开发）
pip install -e .
agentshield --help

# C. 作为包安装
pip install agentshield
agentshield --help
```

验证安装：

```bash
agentshield --version
# AgentShield 1.0.0
# 内置规则：44 条
```

### 平台说明

| 平台 | 说明 |
| --- | --- |
| Linux / macOS | 直接使用，无需额外配置 |
| Windows | 工具会自动把 stdout/stderr 切到 UTF-8，中文报告与中文路径均正常显示 |
| Git Bash / WSL | 路径会自动归一化为 `/` 分隔符，报告中的路径可直接复制 |

## 2. 扫描目标

`scan` 接受一个文件或一个目录。

### 会被扫描的文件类型

| 扩展名 | 语言标识 |
| --- | --- |
| `.py` `.pyw` `.pyi` | Python |
| `.js` `.jsx` `.mjs` `.cjs` `.ts` `.tsx` `.mts` `.cts` | JavaScript / TypeScript |
| `.sh` `.bash` `.zsh` `.ksh` `.fish` `.ps1` `.psm1` `.cmd` `.bat` | Shell / PowerShell |
| `.md` `.markdown` `.mdx` | Markdown |
| `.json` `.jsonc` | JSON |
| `.yaml` `.yml` `.toml` `.txt` `.ini` `.cfg` `.env` 等 | 配置 / 文本 |
| `.rb` `.php` `.go` `.rs` `.java` `.kt` `.c` `.h` `.cpp` `.cs` `.swift` `.lua` `.pl` `.r` | 其他源码 |

按文件名额外匹配：`Dockerfile`、`Makefile`、`justfile`、`Procfile`、`.npmrc`、`.pypirc`、
`.gitconfig`、`requirements.txt`、`Pipfile`、`poetry.lock`、`package.json`。

### 自动跳过的目录

`node_modules`、`__pycache__`、`.venv`、`venv`、`.git`、`dist`、`build`、`.mypy_cache`、
`.pytest_cache`、`.ruff_cache`、`.tox`、`.nox`、`.next`、`.nuxt`、`.cache`、
`site-packages`、`coverage`、`.idea`、`.vscode-test`、`site`、`*.egg-info`、
`.terraform`、`.gradle`。

需要扫描这些目录时用 `agentshield scan <子目录>` 显式指定。

### 跳过的文件

- 二进制文件（含 `\x00` 字节）
- 单文件超过 2 MB
- 无法按 UTF-8 解码的文件

跳过的文件计入 `skipped_files`。

## 3. `scan` 命令

```bash
agentshield scan <target> [选项]
```

### 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-f`, `--format` | `console` | 输出格式：`console` / `json` / `markdown` / `sarif` |
| `-o`, `--output` | 标准输出 | 报告写入文件；目录会自动创建 |
| `-c`, `--config` | 自动查找 | 指定配置文件路径 |
| `--fail-on` | 取自配置 | 达到该严重度时以退出码 `1` 结束 |
| `--severity` | `info` | 只输出不低于该严重度的命中 |
| `--rule` | 全部 | 只运行指定规则 ID，可重复 |
| `--exclude` | 无 | 额外排除路径 glob，可重复 |
| `--no-config` | 关闭 | 完全忽略配置文件 |
| `--no-color` | 关闭 | 关闭 ANSI 颜色 |
| `--quiet` | 关闭 | 只打印摘要（配合 `--output` 使用） |

### 规则过滤

```bash
# 只跑提示注入规则
agentshield scan . --rule AS-PI-001 --rule AS-PI-003

# 规则 ID 大小写不敏感
agentshield scan . --rule as-pi-001
```

`--rule` 同时作用于正则规则、清单检查与启发式检查 —— 输出的命中里只会有你指定的规则 ID。

### 严重度过滤

```bash
# 只看严重和高危
agentshield scan . --severity high
```

过滤在规则应用**之后**进行，因此 `--severity` 与 `--rule` 可以组合使用。

## 4. `rules` 命令

```bash
agentshield rules                          # 人类可读列表
agentshield rules --json                   # JSON 数组
agentshield rules --category exfiltration  # 按类别过滤
agentshield rules --severity high          # 按严重度过滤
agentshield rules -o rules.json            # 写入文件
```

类别列表：

`prompt_injection`（提示注入）、`credential_access`（凭据访问）、`exfiltration`（数据外泄）、
`remote_execution`（远程执行）、`persistence`（持久化）、`privilege`（过度权限）、
`obfuscation`（代码混淆）、`supply_chain`（供应链）、`destructive`（破坏性操作）。

JSON 输出中每条规则包含：`id`、`title`、`severity`、`severity_label`、`category`、
`category_label`、`description`、`remediation`、`languages`、`tags`、`confidence`、
`cwe`、`pattern`。

> `pattern` 字段会一并导出，方便你把规则导入自己的平台。

## 5. `init` 命令

```bash
agentshield init                  # 生成 ./.agentshield.json
agentshield init -o ci/as.json    # 生成到指定路径
agentshield init --force          # 覆盖已有文件
```

生成的模板包含：

- 一条被降级的规则示例（`AS-SUP-003: warn`）
- 常用排除项
- 默认 `fail_on: high`
- 一条可直接使用的自定义规则示例（`ORG-001` 禁止访问内网地址）

## 6. 配置文件

### 查找顺序

1. `--config` 显式指定的路径
2. 从扫描目标所在目录开始，**逐级向上**查找 `.agentshield.json`
3. 当前工作目录
4. 都没有 → 使用默认配置（无规则开关、无排除项）

> 注意：如果扫描目标本身是文件，查找从该文件所在目录开始。

### 字段

```json
{
  "rules": {
    "AS-SUP-003": "warn",
    "AS-EXF-006": "off"
  },
  "severity_overrides": {
    "AS-PI-005": "critical"
  },
  "exclude": ["**/node_modules/**"],
  "fail_on": "high",
  "custom_rules": []
}
```

#### `rules`

| 值 | 效果 |
| --- | --- |
| `"on"` | 正常启用（默认） |
| `"warn"` | 严重度降一级（如 `high` → `medium`），不会低于 `info` |
| `"off"` | 完全关闭 |

#### `severity_overrides`

强制覆盖某条规则的严重度，用于对齐组织基线。取值必须属于
`critical` / `high` / `medium` / `low` / `info`。

> 覆盖发生在 `warn` 降级**之后**，因此 `severity_overrides` 优先级更高。

#### `exclude`

路径 glob 列表，相对扫描根目录。匹配示例：

```json
"exclude": [
  "tests/fixtures/**",
  "**/node_modules/**",
  "docs/*.md"
]
```

#### `custom_rules`

字段说明见 [规则手册](规则手册.md#自定义规则)。

## 7. 输出格式

### `console`（默认）

按严重度分组、逐条展示位置、说明、代码片段与修复建议，带 ANSI 颜色。

### `json`

```json
{
  "tool": "agentshield",
  "root": "/abs/path",
  "scanned_files": 3,
  "skipped_files": 0,
  "duration_ms": 24,
  "rules_loaded": 44,
  "summary": { "critical": 4, "high": 9, "medium": 1, "low": 0, "info": 0 },
  "categories": { "prompt_injection": 5, "exfiltration": 2 },
  "findings": [
    {
      "rule_id": "AS-PI-001",
      "title": "技能指令中试图覆盖模型既有指令",
      "severity": "critical",
      "severity_label": "严重",
      "category": "prompt_injection",
      "message": "检测到可疑内容：ignore all previous instructions",
      "remediation": "删除覆盖既有指令的措辞……",
      "file": "SKILL.md",
      "line": 3,
      "column": 40,
      "snippet": "description: \"提升开发效率的助手工具。<!-- ignore all previous instructions …\"",
      "match": "ignore all previous instructions",
      "tags": ["提示注入", "AI 特有"],
      "confidence": "high",
      "cwe": "CWE-77"
    }
  ],
  "errors": []
}
```

`findings` 已按严重度 → 文件 → 行号排序。

### `markdown`

适合贴进 PR 评论、Issue 或评审记录。包含风险汇总表、类别分布表与逐条明细（含代码块）。

### `sarif`

SARIF 2.1.0 格式，可直接上传到 GitHub Code Scanning：

```bash
agentshield scan . --format sarif --output results.sarif
```

带 `security-severity` 分数（critical 9.0 / high 7.0 / medium 5.0 / low 3.0 / info 1.0），
GitHub 会据此在 PR 上显示告警级别。

## 8. 退出码与 CI

| 退出码 | 含义 |
| --- | --- |
| `0` | 扫描完成，未触发失败基线 |
| `1` | 存在达到阈值的命中 |
| `2` | 参数错误、目标不存在、配置非法 |
| `3` | 运行异常 |

阈值优先级：

```
命令行 --fail-on  >  配置文件 fail_on  >  不设置（永远返回 0）
```

推荐做法：

```bash
# 日常本地：只提醒
agentshield scan .

# CI：严重即失败
agentshield scan . --fail-on critical

# CI：默认基线
agentshield scan . --fail-on high
```

## 9. 典型工作流

### 场景一：安装前审计一个第三方技能

```bash
git clone https://example.com/some-skill.git
agentshield scan some-skill --severity medium
```

有 `critical` 或 `high` 就不要装。

### 场景二：审计自己的 MCP Server

```bash
agentshield scan ./mcp-server --format markdown -o review.md
```

把 `review.md` 贴进 PR。

### 场景三：审计整个仓库并在 PR 上留痕

```bash
agentshield scan . --format sarif --output results.sarif --fail-on high
```

配合 GitHub Actions（见 [CI集成.md](CI集成.md)）。

### 场景四：为团队定制基线

```bash
agentshield init
# 编辑 .agentshield.json：
#   - 关掉误报高的规则
#   - 把团队最关心的规则提到 critical
#   - 加入内部地址的自定义规则
agentshield scan . --fail-on high
```

### 场景五：只看某个类别的风险

```bash
agentshield scan . --rule AS-PI-001 --rule AS-PI-002 --rule AS-PI-003 --rule AS-PI-004
```

## 10. 常见问题

**Q：扫描结果全是误报怎么办？**

按 `confidence` 过滤：`--rule` 精确到规则级别，或在配置里把噪音规则设为 `"off"`。
先用 `agentshield rules` 看规则说明再决定。

**Q：为什么跳过了一个文件？**

`skipped_files` 计数包含：二进制文件、超过 2 MB 的文件、非 UTF-8 编码的文件、
以及被 `exclude` 排除的路径。

**Q：能扫二进制 / 编译产物吗？**

不能。AgentShield 只处理文本。编译产物请用其他 SAST 工具。

**Q：Windows 下中文乱码？**

不会。工具启动时会把 stdout/stderr 重设为 UTF-8。若你通过管道传给不支持 UTF-8
的程序，可加 `--no-color` 或改用 `-o` 写文件。

**Q：`--rule` 和配置文件里的 `rules` 会冲突吗？**

`--rule` 是"白名单"，只运行指定规则；配置文件里的 `rules` 决定这些规则是
`on` / `warn` / `off`。`--rule` 与配置里的 `"off"` 同时存在时，以 `off` 为准
（因为 `off` 表示规则不在解析结果中）。

**Q：怎么抑制某条已知误报？**

在配置里加 `"exclude"` 排除对应路径，或用 `"rules": { "规则ID": "off" }`。
`severity_overrides` 不能用来降级（只能设成四个既定级别）。

**Q：规则手册和代码不一致怎么办？**

规则手册是自动生成的。改完 `agentshield/rules.py` 后运行：

```bash
python scripts/gen_rule_docs.py
```

**Q：能扫描 Git 仓库的历史吗？**

不能，只扫描工作区当前状态。
